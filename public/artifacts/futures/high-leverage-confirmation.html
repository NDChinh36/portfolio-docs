BA Annotations
1
Modal Trigger Condition
Modal appears only when leverage is at or above the configured risk threshold. Threshold is a system config value — not hardcoded — so it can be updated without a deploy.
BR-LEV-01
2
Leverage Value Display
The exact leverage value is shown prominently so the user cannot claim they didn't see it. This is also captured in the audit log when confirmation is accepted.
AUDIT LOG
3
Estimated Liquidation Price
Shown in red inside the confirmation modal — reinforces the BA decision to show this before order submission, not just in Position Management. This is the single most important risk number for the user.
BA DECISION
4
Mandatory Acknowledgement
User must actively check the acknowledgement box. Passive reading is not enough. This creates an explicit consent record and shifts accountability to the user for high-risk orders.
COMPLIANCE
5
Once-per-Session Rule
Modal appears only once per session to avoid annoying pro traders who frequently adjust leverage. Session state resets on logout or session expiry. Trade-off: reduces safety repetition but improves UX for power users.
UX TRADE-OFF
6
Confirmation Audit Event
Confirm Order click triggers: (a) store session flag, (b) log event with leverage value, timestamp, and user ID, (c) pass control back to order submission flow. Cancel clears acknowledgement without logging.
SYSTEM EVENT
