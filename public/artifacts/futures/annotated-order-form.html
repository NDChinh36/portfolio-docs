BA Annotations & Design Decisions
1
SCOPE · OUT OF MVP
Cross Margin — Deferred to v2
Cross Margin increases formula complexity and introduces edge cases that are 2× harder to validate (shared margin pool, liquidation cascade scenarios). Deferred to reduce launch risk. Isolated Margin covers ~85% of new user flows.
→ Margin Mode toggle
2
BR-LEV-01
Leverage ≥ 20x Confirmation Trigger
When leverage ≥ 20x, a mandatory confirmation popup must appear before the order is submitted. This prevents accidental high-risk orders from users who scroll the slider without reading. The threshold was aligned with exchange industry standard (Binance, Bybit).
→ Leverage slider (current: 20x)
3
BA DECISION
Liquidation Price — Shown on Order Form
Original dev spec placed this only in Position Management. BA decision: surface it during order entry too. User research showed "surprised by liquidation" was a top-3 CS ticket category. Liq. price recalculates on every input change (price, qty, leverage).
→ Est. Liquidation Price field (red)
4
FORMULA
Required Margin Preview
Calculated as Position Size ÷ Leverage. Must be compared against Available Balance before submit is enabled. If Required Margin > Available Balance, submit is disabled with an inline error state.
→ Required Margin row
5
DISABLED STATE
Submit Button — Two Disable Conditions
Button is disabled if: (A) Required Margin > Available Balance, OR (B) Leverage ≥ 20x AND user has not acknowledged the risk confirmation popup. Both conditions must be clear in the UI via distinct visual states.
→ Open Long Position button (locked)
6
BR-LEV-01
High Leverage Warning — Must Be Pre-Modal
Warning banner must be visible on the Order Form itself, not only inside the confirmation popup. This ensures the risk message is seen before the user clicks "submit" — satisfying compliance requirement that risk disclosure precedes order action.
→ Yellow warning banner
