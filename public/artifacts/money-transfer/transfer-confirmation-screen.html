Receiver Validation Hiển thị avatar + tên trước confirm để user xác nhận đúng người nhận. Edge case: receiver không active → show error trước confirm screen, không tiếp tục luồng. Prevents fund loss to inactive accounts.

Balance Validation Validate theo available = total − margin_locked. User có Futures open position không được transfer hết total_balance → liquidation risk. BA Decision 2: thêm API call lấy margin_locked trước bước validate.
C
Transaction State Machine 5 states: PENDING → PROCESSING → SUCCESS (happy path) hoặc FAILED → ROLLBACK (error path). State transitions được BA spec rõ ràng trong PRD — dev implement theo state machine, không tự xử lý edge case.
D
Rollback Policy Transfer thất bại sau debit (system failure) → auto rollback tức thì. Reversed transaction trong 24h → rollback reward (nếu có). Log incident + notify user. BA define rollback scenarios trong Edge Case Register.
E
Duplicate Prevention Mỗi transaction có idempotency_key unique (client-generated). Submit cùng key 2 lần → server trả về kết quả giao dịch đầu, không tạo duplicate. Prevents double-submit khi network timeout.
