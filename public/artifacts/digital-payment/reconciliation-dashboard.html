BA Annotations — Design Decisions & Business Rules
1
Dual-Status Display: Core Detection Logic
Wallet status and Gateway status are always shown as two separate columns. A transaction is only considered reconciled when both statuses match. Any inconsistency between wallet ledger and gateway response is the primary signal for exception handling. Do not merge these into a single status column.
2
Unknown Status: Inquiry-First Rule
An Unknown reconciliation status means the gateway has not yet confirmed the final outcome. The wallet must NOT be updated (debit or refund) until reconciliation completes. Ops must trigger a Retry Inquiry via the gateway's status API. Unknown status expires to FAILED after the reconciliation window (T+1 EOD).
3
Refund Actions: Finance Approval Required
Refund actions require explicit Finance team approval before execution. The system must log: operator ID, timestamp, refund reason, and approval reference. Refunds must be processed through the wallet's reversal API — not a new credit transaction. Audit trail is mandatory for regulatory compliance.
4
Manual Resolution: Operator Accountability
Any manual Mark Resolved action must capture: operator name (from authenticated session), resolution reason (from a controlled vocabulary list), and a free-text note. Resolution without these fields must be blocked. All manual resolutions are surfaced in the daily exception report sent to Finance and Compliance.
