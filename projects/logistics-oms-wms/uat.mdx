## Overview

### Scope UAT

UAT cho hệ thống OMS/WMS của VietFulfill bao gồm toàn bộ luồng xử lý đơn hàng từ khi nhận order từ các sales channel đến khi đơn được giao thành công hoặc hoàn hàng về kho. UAT **không** bao gồm: kiểm thử performance/load, kiểm thử bảo mật cấp hạ tầng, và các module báo cáo tài chính.

### Người Thực Hiện

| Vai trò | Trách nhiệm | Đại diện |
|---|---|---|
| **QA Lead** | Lập kế hoạch, phân công, tổng hợp kết quả | 1 người |
| **Business Analyst** | Verify expected result khớp với spec | 1 người |
| **Seller Representative** | Test cases liên quan đến Seller Portal | 1–2 người |
| **Warehouse Staff** | Test cases liên quan đến WMS (picking, packing) | 2–3 người |
| **CS** | Test cases liên quan đến exception handling | 1 người |
| **Operation Manager** | Verify alert, SLA breach, supervisor flow | 1 người |

### Môi Trường

| Thành phần | Giá trị |
|---|---|
| **Environment** | UAT (tách biệt hoàn toàn với Production) |
| **OMS URL** | `https://oms-uat.vietfulfill.vn` |
| **WMS URL** | `https://wms-uat.vietfulfill.vn` |
| **Seller Portal URL** | `https://portal-uat.vietfulfill.vn` |
| **Carrier Integration** | Sandbox mode (GHN Sandbox, GHTK Sandbox) |
| **Sales Channel Webhook** | Dùng Postman Collection hoặc mock webhook server |
| **Thời gian thực hiện** | Sprint UAT: 5 ngày làm việc |

### Naming Convention — Test ID

`UAT-[GROUP]-[NUMBER]` — Ví dụ: `UAT-HAPPY-01`, `UAT-OOS-03`, `UAT-CANCEL-LATE-02`

## Test Scenarios

### Group 1: Happy Path — Full Order Fulfillment (`UAT-HAPPY-xx`)

**[UAT-HAPPY-01] COD order từ Shopee — giao thành công lần đầu**

| | |
|---|---|
| **Preconditions** | Seller A đã onboard. SKU `SKU-001` tồn kho ≥ 1 tại bin `BIN-A1`. GHN Sandbox hoạt động. |
| **Steps** | 1. Gửi Shopee webhook `order_paid` — `external_order_id = SHP-20240601-001`, COD, 1x `SKU-001`, địa chỉ TPHCM. / 2. Verify OMS tạo order status `VALIDATING`. / 3. Verify sau validation, status → `ALLOCATED`, stock `SKU-001` giảm 1 unit. / 4. Verify WMS tạo Pick Task, Picker nhận task trên WMS app. / 5. Picker scan barcode `BIN-A1`, scan barcode `SKU-001`, confirm số lượng 1. / 6. Verify status → `PICKED`. / 7. Packer đóng gói, in label GHN, scan xác nhận. / 8. Verify status → `PACKED`. / 9. GHN Sandbox gửi webhook `picked_up`. / 10. Verify status → `IN_TRANSIT`. / 11. GHN Sandbox gửi webhook `delivered`. / 12. Verify OMS status → `DELIVERED`, Seller Portal hiển thị "Đã giao thành công". |
| **Expected Result** | Order flow qua đủ status: VALIDATING → ALLOCATED → PICKED → PACKED → IN_TRANSIT → DELIVERED. Tồn kho giảm đúng 1 unit. Seller Portal hiển thị tracking đầy đủ. COD amount được ghi nhận đúng. |
| **Priority** | High |

|---|---|

| **Steps** | 1. Gửi TikTok Shop webhook `ORDER_STATUS_CHANGE` (status = `AWAITING_SHIPMENT`), prepaid, 3 line items: 2x `SKU-A`, 1x `SKU-B`, 3x `SKU-C`. / 2. Verify OMS tạo order status `VALIDATING`. / 3. Verify OMS chuyển `ALLOCATED`, lock đồng thời 3 SKU đúng số lượng. / 4. Verify WMS tạo Pick Task. / 5. Picker lần lượt scan từng bin, từng SKU. / 6. Verify status `PICKED` chỉ khi TẤT CẢ line items đã pick xong. / 7. Packer đóng gói, in label GHTK. / 8. GHTK Sandbox gửi webhook `picked_up` → `delivered`. / 9. Verify status `DELIVERED`, tồn kho 3 SKU giảm đúng số lượng. |
| **Expected Result** | Order multi-SKU được allocate và pick đầy đủ. Tất cả SKU tồn kho giảm chính xác. GHTK tracking number hiển thị trên Seller Portal. |
| **Priority** | High |

### Group 2: Out of Stock (`UAT-OOS-xx`)

**[UAT-OOS-01] Order nhận vào nhưng SKU hết hàng hoàn toàn**

| | |
|---|---|
| **Preconditions** | `SKU-OOS01` tồn kho = 0. Webhook order từ Shopee chứa 1x `SKU-OOS01`. |
| **Steps** | 1. Gửi Shopee webhook order với 1x `SKU-OOS01`. / 2. Verify OMS attempt allocation → fail vì tồn kho = 0. / 3. Verify order chuyển sang status `EXCEPTION` với reason code `OOS_FULL`. / 4. Verify exception được tạo trong Exception Queue. / 5. Verify CS nhận notification. / 6. Verify tồn kho `SKU-OOS01` KHÔNG thay đổi (vẫn = 0). |
| **Expected Result** | Order vào `EXCEPTION` với reason `OOS_FULL`. Tồn kho không bị trừ âm. Exception Queue có entry. |
| **Priority** | High |

---

**[UAT-OOS-02] Order có 3 SKU — 2 đủ hàng, 1 hết — partial OOS handling**

| | |
|---|---|
| **Preconditions** | `SKU-A` tồn kho = 5, `SKU-B` = 3, `SKU-OOS02` = 0. Order: 1x `SKU-A`, 1x `SKU-B`, 1x `SKU-OOS02`. |
| **Steps** | 1. Gửi webhook order với 3 line items. / 2. Verify OMS KHÔNG partial-allocate (không pick `SKU-A` và `SKU-B` trước khi resolve OOS). / 3. Verify order vào `EXCEPTION` với reason `OOS_PARTIAL`, liệt kê SKU nào thiếu. / 4. Verify reserved stock của `SKU-A` và `SKU-B` được HOLD trong thời gian chờ xử lý. |
| **Expected Result** | System không tự động partial-fulfil. Stock `SKU-A` và `SKU-B` được hold. Exception detail liệt kê đúng SKU thiếu. |
| **Priority** | High |

**[UAT-OOS-03] Stock bổ sung sau khi order vào OOS — retry allocation**

| | |
|---|---|
| **Preconditions** | Order từ `UAT-OOS-01` đang `EXCEPTION/OOS_FULL`. `SKU-OOS01` tồn kho = 0. |
| **Steps** | 1. Warehouse nhập hàng mới: GRN cho `SKU-OOS01`, nhập 10 units vào bin `BIN-B2`. / 2. Verify WMS cập nhật tồn kho `SKU-OOS01` = 10. / 3. Verify OMS nhận stock update và tự động retry allocation. / 4. Verify order được allocate thành công, chuyển từ `EXCEPTION` → `ALLOCATED`. / 5. Verify tồn kho `SKU-OOS01` giảm từ 10 → 9. / 6. Verify Exception Queue đóng entry. |
| **Expected Result** | Sau khi GRN, OMS retry allocation thành công. Order thoát exception và tiếp tục luồng bình thường. |
| **Priority** | High |
